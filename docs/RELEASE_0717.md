# Forge Engine 0.7.17 — GPU Particle Runtime & Editor refinements

## Baseline and compatibility
Built from the exact 0.7.16 source ZIP with the confirmed GPU Particle Lab type-cast hotfix. No dependency or profile changes, no Auto Rig/automatic animator. Existing demo files are unchanged. New scene settings deserialize with legacy defaults: GPU particles off, one light per sprite, hard shadows. The feature is opt-in, 2D only. The minimal feature configuration explicitly rejects scenes requiring the lighting/GPU feature. No Rust/WGSL runtime verification was possible in this authoring environment.

## Added source implementations
- Shared `gpu_particles` plugin registered in Editor and Player. Render graph dispatch before the camera driver, per-emitter persistent GPU storage buffers, fixed 60 Hz simulation (up to four steps per frame), translucent Material2d draw using GPU positions without CPU readback. Supports continuous emitters, color/size/velocity/lifetime/rate/spread, import of PNG/JPEG particle textures up to 512x512, five presets plus custom. Editor previews GPU emitters outside play; Play pause stops simulation. CPU path remains for unselected emitters, isometric projects, and projects with GPU particles off. New feature shares the existing `lighting` Cargo flag, no dependency change.
- Bounded experimental backend: at most eight eligible emitters, each up to 128 slots; emitters beyond the budget or above 600,000 world-pixel squared bounding area remain CPU-rendered. Rates above capacity are capped; simulation positions are emitter-local (move with emitter). Fragment shader loops over slots on each emitter quad; not instanced particle rendering, may be expensive at large screen sizes/zoom. No unsupported-device automatic fallback; disable GPU particles if needed. Textures use bounded synchronous loading, no live reload of unchanged path.
- GPU lighting: up to three strongest lights per sprite (centre-based selection); four static axis-aligned blocker bounds per light, three-ray approximate penumbra with configurable softness 0–32 px, normal-map path preserved. Not shadow maps or physically accurate soft shadows. Default one light and zero softness preserve prior settings. Avoid marking material assets changed if parameters are unchanged.
- Docking: optional tab stacks for panels sharing one of the four existing zones, persisted selection; existing separate resizable docked and floating panels retained. Not arbitrary nested split trees. Modest dark palette refinement, not full editor redesign.
- Sprite animation: frame-strip seeking respects variable frame durations; auto-state and Lua clip transition timestamps restart clip playback. Existing sprite sheet and Aseprite tools retained. Not a new visual FSM.
- Audio: playback speed/pitch setting at Player scene sound startup, legacy mixer and distance attenuation retained. No EQ, reverb, true stereo spatial positioning or new audio graph.
- Visual UI: duplicate widget and quick grouped inventory-label/control-menu templates, previous layout preview and HUD groups retained. Inventory templates are static layout labels, not inventory game logic. No full visual tree editor.
- Profiler: configured emitter quads, allocated slots, storage payload bytes and scene light count; existing process RSS, texture-cache estimates and UI frame time. Counts are not measured draw calls, GPU timings, or total VRAM. No measured performance or executable-size improvement.
- Stability: corrected Lab E0277, scoped suppression of ShaderType-generated unused check helper warnings in gpu_scene module, QUICK_CHECK includes gated GPU examples, lock migration from 0.7.16 retains dependency pins. Three new Rust regression tests (scene/legacy defaults/budget); not run here. Existing tests retained; build script adds headless model QA of new fixture.

## Windows validation sequence
1. Back up v0.7.16 and confirmed v0.7.15 release. Apply update ZIP directly to existing source folder containing Cargo.toml; keep Cargo.lock and target. Full ZIP is for fresh source only.
2. Run QUICK_CHECK.bat (now includes GPU Lab examples). Check forge-quick-check.log. Run QUICK_BUILD.bat then RUN_EDITOR_DEBUG.bat if successful.
3. Run RUN_GPU_SCENE.bat (legacy lighting), GPU_PARTICLE_LAB.bat (isolated reference), then RUN_GPU_PARTICLES_SCENE.bat (five emitters, three lights, normal map, soft shadows). Observe moving particles, fading, colored lights, moving shadows with WASD, custom snow texture. Open examples/gpu_particles/project.forge.json in Editor and test live preview, edit presets, play/pause, toggle GPU particles and light count, save/reopen. Try docking two panels to one zone and enabling the tabs checkbox, then Save dock.
4. If visual issues arise, capture console including WGSL pipeline errors, screenshots and adapter details. Run BUILD_WINDOWS.bat only after quick and visual tests pass. No new EXE or portable package is included here.
