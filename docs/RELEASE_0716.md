# Forge Engine 0.7.16 — GPU & Editor Integration (experimental source)

## Verified baseline
User-supplied 0.7.15 Windows logs: full and minimal checks succeeded, 37 + 32 test executions succeeded, release and four staged smoke checks succeeded. The user manually confirmed lighting and shadows in the original GPU Lighting Lab. This is evidence for 0.7.15 only.

## Changes
- Shared opt-in 2D `GpuScenePlugin` for the editor's native viewport, game preview and Player. Embedded WGSL via `Material2d`; albedo, atlas UVs, tint, tangent-space normal map, ambient and strongest light per sprite, four nearby static AABB occluders per sprite. Hard shadows are calculated per fragment. Legacy CPU path is the default; isometric scenes use the legacy path. Enable via Gameplay PRO > GPU lighting. The new pipeline has not been compiled or visually tested here; disable the setting if it renders incorrectly. It is not an automatic pipeline-error fallback. A selected light or occluder limit can cause visual discontinuities; no soft shadows or unlimited lights.
- Reuse existing `ProductionObject.normal_map`, linear (not sRGB) upload. Inspector > Sprite > Import Normal Map copies to project assets; Clear normal removes the reference. Save As, rename and resource database support the same field. Flat normal fallback. Imported normals capped at 2048×2048; resident cache capped at eight distinct entries (up to 128 MiB raw, not whole RAM/VRAM). Normal decoding is synchronous on first use; restart or disable/re-enable GPU mode to refresh edited normal textures. Normal atlas should have the same layout as the color atlas. Mesh handles reused, unchanged material parameters not rewritten.
- Separate optional GPU Particle Lab: 128 particles in a storage buffer, compute pass ahead of camera draw, fragment rendering from the buffer. Fixed step per frame, no readback; not yet integrated with scene emitters and not a scalable production particle renderer. CPU particles unchanged. GPU_CHECK checks Rust examples, not WGSL runtime. Run GPU_PARTICLE_LAB.bat to see the result.
- Workspace: panel context menus to move left/right/top/bottom/float; Save dock persists both placement and floating preferences. Existing drag/drop and resizing retained. No arbitrary nested tab split tree. Small dark theme and spacing adjustments, existing vector icons retained; not a complete Godot-style redesign.
- Sprite sheet grid assistant: read image dimensions, enter cell width/height, Apply grid / fit frame. Reject partial cells, grid >128×128, invalid FPS. Existing clip editor, Aseprite, timeline, and animation logic retained.
- Performance: deduplicate filesystem metadata checks within 500 ms per viewport texture path; bounded normal cache; reuse meshes/material handles. CPU light computation still present in existing sprite path, including when GPU enabled. No claims of increased FPS, smaller EXE or lower measured memory. The added GPU code could increase executable size and GPU load.
- Build: unchanged dependency constraints, features and profiles. Shared lock migration changes only root forge_engine package version from 0.7.14 or 0.7.15 to 0.7.16, retaining dependency pins. No lockfile or target directory is shipped in either source archive. Keep your local Cargo.lock and target. QUICK_CHECK checks sources, QUICK_BUILD incrementally builds debug binaries, RUN_EDITOR_DEBUG launches that executable directly. BUILD_WINDOWS retains the full regression suite and now checks GPU examples too. First compile of new shader features and changed source can still take time.
- Three new Rust tests: legacy GPU defaults, loading sample scene, grid validation. They have not been run here. Existing smoke and editor QA remain. All 24 original files under examples/ preserved byte for byte. No Auto Rig or automatic animator integration.

## Windows QA sequence
1. Back up the confirmed v0.7.15 portable ZIP, projects and source folder; extract the update into the existing source folder, leaving Cargo.lock and target untouched. New full archive is also available, but it does not reuse a separate directory's target automatically.
2. Run QUICK_CHECK.bat; send forge-quick-check.log if it fails. Then QUICK_BUILD.bat and RUN_EDITOR_DEBUG.bat. Open existing project with GPU off to check regression.
3. Run RUN_GPU_SCENE.bat, move the light using WASD; check hard shadow movement and relief on the panel. Open examples/gpu_scene/project.forge.json in editor and verify viewport and Play. Toggle GPU lighting off/on, save/reopen, import a matching map and test Save As. The example is not a platformer and is intentionally excluded from the platformer-specific --smoke test.
4. Run GPU_CHECK.bat, then GPU_PARTICLE_LAB.bat; report log, window contents and any shader errors. Original GPU_LIGHTING_LAB.bat remains available. GPU lab steps do not establish full runtime stability.
5. Run BUILD_WINDOWS.bat only once quick checks and visual tests pass. Send forge-check.log and build-info.json from dist for size comparison. Keep the earlier portable archive if the new build fails.
