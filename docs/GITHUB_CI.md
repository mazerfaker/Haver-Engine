# Forge Engine: GitHub stabilization policy

Repository: private `mazerfaker/Forge-Engine`. Baseline: v0.7.41 source snapshot. The archive tags `source-v*` reconstruct historical source releases; they are NOT proof of successful CI. No engine features are replaced by the import.

## Build gate
- Windows hosted runner x64 MSVC, recorded Rust version, locked dependencies, cache Cargo registry and target via rust-cache.
- Existing Cargo.lock is never regenerated by CI. First missing lock on main is generated once and committed; the build checks the resulting commit, not the earlier unlocked SHA. A locally retained lock can be supplied before import. If dependency changes become necessary, update the lock explicitly in a separate reviewed commit. Root package version-only migrations may use tools/prepare_lock.ps1.
- Python validators (including executable file-transaction tests), cargo check, full and minimal Rust tests, modular feature checks, headless Signal Lost and editor model QA, release compilation, staged player smoke. Isolated GPU instancing/audio lab checks are reported separately; their failures must not be mistaken for success. GUI, GPU rendering, actual audio and VRAM/performance require hardware validation.
- Windows portable artifacts only upload after required gates succeed. Logs and lockfile upload even on failure where available. Check Actions run and exact built commit. Artifacts retained for 30 days; download durable releases locally. No automatic stable release or tag is created. GitHub hosted Windows time and storage are subject to account quotas.
- `tools/package_source.py` exports full tracked source (including the committed lockfile) and an overlay patch against the latest older source tag. It excludes Cargo.lock and target from patch and records any deletions for manual review. Never blindly overwrite an existing working project; retain local lock and target, migrate root version only when applicable, back up before applying deletions. Source tags can be added for verified future source snapshots without naming them stable.

## Roadmap retained
1. v0.7.42 stabilization: actual compiler logs, minimal fix commits, repeat CI until required checks pass, then manual QA of GUI, audio, rendering and Windows portable startup.
2. Animation Studio Ultimate: advanced Bezier curves, multi-channel timeline and preview; Asset Database Ultimate: background indexing, transaction journals and recovery.
3. Audio Mixer Ultimate: compressor, noise gate, diagnostics and DSP; Lighting Ultimate: materials, normals and soft shadows; Prefab Graph Ultimate: visual subtree transfer and dependent-instance migration; Editor Design Ultimate; performance profiling CPU/GPU/RAM/VRAM.
4. GPU Instancing Runtime only after successful isolated hardware lab test; Save Game PRO slots and migrations; Android runtime and APK preparation; v0.8.0 release gate before broader v1.0 roadmap.
5. Preserve native Rust/Bevy/egui/Rapier/Lua architecture, 2D/2.5D, Ukrainian/English localization and all existing demos. No Auto Rig or automatic animator.

For each version: inspect actual CI failure -> fix the specific source -> commit -> rerun -> record status and exact commit. Do not describe an uncompiled source snapshot as a stable build. Do not claim measured performance without measurements.
